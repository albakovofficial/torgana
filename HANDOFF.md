## 1. Идея и позиционирование

- **1.44.0 — подарки модератора** (решение владельца): в карточке пользователя в модерации, блок «Платные услуги» (виден всегда, кроме заблокированных): «Подарить тариф» — любому пользователю, и без подтверждённого ИП (витрина тогда под его именем; купить тариф самому по-прежнему можно только ИП/компании); «Подарить рекламу» — опубликованному объявлению, 1–90 дней (`POST /api/admin/listings/:id/promo`); «Подарить продвижение» — XL, рамка и/или до двух меток на 7 дней, опубликованному или ждущему публикации (`POST /api/admin/listings/:id/boost`). Подарок идёт тем же путём, что и оплата (`startPromo` в lib/promo.js, `startBoost` и проверка выбора `pickBoost` в lib/boost.js), с ценой 0 и без платежа; продавец получает уведомление, в журнале — «Подарил тариф / рекламу над поиском / продвижение в ленте». Снимается так же — «Отключить». Тест — `tests/hardening.test.js`, проверка вёрстки — `admin-gift-boost`, `admin-gift-promo`.
- **1.43.1 — без подписи «Продвигается» на карточках** (решение владельца): значок убран из ленты, поиска, избранного и XL; продвижение видно только по XL, рамке и меткам. Тексты окна «Продвижение», «Для бизнеса», «Как искать», оферты 7.7 и Правил поправлены. У автора статус «Продвигается · ещё N дней» в своём объявлении и «Моих объявлениях» остался.
- **1.43.0 — поиск с опечатками, лёгкие фото, ответы продавца, значок «Продвигается» на фото** (макеты — холст «Торгана — следующие улучшения»):
  - **Поиск:** слово из 3+ букв ищется по триграммному индексу SQLite FTS5 `listings_fts` (внешнее содержимое — `listings.search_text`, триггеры `listings_fts_ai/ad/au`; при первом запуске индекс строится сам). Когда подходящих больше 2 000, страница берётся просмотром по дате (`specSql(spec, { fts: false })`) — так быстрее. **Опечатки:** если ничего не нашлось, `correctQuery` (lib/search.js) заменяет незнакомое слово ближайшим из словаря слов опубликованных объявлений (1 правка для 4–5 букв, 2 — для 6+, при равенстве — более частое; словарь — раз в 10 минут, `searchVocab` в server.js); ответ несёт `corrected`, над выдачей — «Показаны результаты по запросу «…»» и ссылка «Искать «…», как написано» (`exact=1`). Описано в «Как искать».
  - **Лёгкие копии фото:** браузер при загрузке делает копию 640 px (WebP, где умеет, иначе JPEG) и шлёт её полем `thumb` в `/api/uploads`; сервер хранит её рядом (`uploads.thumb`) и подставляет в карточки ленты, поиска, избранного, рекламы, чатов, «Моих объявлений» (`COALESCE(NULLIF(p.thumb, ''), p.file)`); страница объявления — оригинал. Удаляется вместе с фото (`removeUploadFiles`). У старых фото копии нет — показывается оригинал.
  - **Как быстро отвечает продавец** (`replyStats` в server.js, `seller.reply` в `/api/listings/:id`): по чатам за 30 дней — от первого сообщения покупателя до первого ответа продавца; показывается только при 5+ чатах (неотвеченный считается, когда покупатель ждёт больше суток); медиана → «Отвечает за час / за 1–3 часа / в течение дня / за 1–2 дня», доля отвеченных — «N из 10 чатов получают ответ». Кэш 10 минут (`REPLY_CACHE_MS` для тестов).
  - **«Продвигается» — значком на фото** (`.b-tag.mark`): у обычной карточки — внизу слева, под «Новое» / «Цена упала» (общий блок `.b-low`), у XL — сверху с метками (внизу цена). Строка под ценой больше не обрезается. Длинная метка в узкой карточке — с многоточием. Удалены мёртвые стили позиционирования бейджей и перекрытые размеры сердечка 1.35.2.
  - Тесты: `tests/improve.test.js`; проверка вёрстки — `search-typo`, `listing-reply`.
- **1.42.0 — переписки по удалённым объявлениям, без сохранённых поисков в базе, без плашки push:**
  - **Удаление объявления** (решение владельца): объявление остаётся в базе со статусом `deleted` (`removeListing` в server.js), переписки покупателей, предложения цены и отзывы по нему сохраняются; в чате — «Объявление удалено» (шапка, список диалогов, колонка справа). Для всего остального его нет: `loadListing(id)` его не отдаёт, `/l/…` и `/api/listings/:id` — 404 «Объявление удалено»; чаты и карточка модерации берут его через `loadListing(id, { deleted: true })`, в истории — «Автор удалил объявление». Оплаченное и не начавшееся продвижение по удалённому — возврат сразу. При удалении профиля навсегда объявления так же скрываются, но фото, видео, описание и характеристики стираются (в чатах остаются название и цена). Политика ПД (сроки хранения) дополнена. Подтверждение удаления в интерфейсе — одна функция `deleteListing`.
  - **Сохранённые поиски удалены из базы** (решение владельца): таблица `saved_searches`, поле `user_alerts.search_id` и их индексы; `user_alerts` пересобирается при первом запуске (уведомления о ценах и подписках сохраняются). Перед установкой автообновление делает копию базы — откат через `deploy/restore.sh`.
  - Панель уведомлений (колокольчик): убрана плашка «Включите push» — пропущенный остаток 1.39.0. Включение — только разовый вопрос после входа и «Настройки → Уведомления».
  - Проверка вёрстки: страница `chat-deleted`; тест `tests/hardening.test.js` — переписка после удаления объявления.
- **1.41.0 — аудит, часть 1 (защита и очистка):**
  - **Критично:** запрос с битой кодировкой в адресе (`/%E0%A4%A`) ронял процесс сайта (`decodeURIComponent` без проверки) — теперь 400. Страховка `process.on('unhandledRejection')` пишет в журнал и владельцу, сайт не падает. Тесты: `tests/hardening.test.js`.
  - `www.torgana.ru` → `torgana.ru` (301, тот же путь) по `PUBLIC_URL`; заголовки `Strict-Transport-Security: max-age=31536000` (без поддоменов — `stats` у SMTP.BZ по http) и `Permissions-Policy`; у файлов `ETag` и ответ 304, `HEAD` без тела.
  - Не больше 30 новых диалогов в час на человека (`conv:<id>`); индекс `favorites(listing_id)`.
  - Подборка за день: без сохранённых поисков — тема по содержанию, кнопка «Избранное» (снижение цен) или «Мои подписки» (была «Мои поиски» → удалённый раздел). Удалены `specMatches`, JOIN с `saved_searches`, дубль `parseCookies` в `lib/ops.js`, ~7,5 КБ стилей старых экранов (сохранённые поиски, плашки уведомлений, раздел «Реклама», старая главная), `isBiz`.
  - Модерация на 320 px: блок «Платные услуги» в карточке пользователя вылезал за экран.
  - Проверка вёрстки: `UI_WIDTHS=320,390,768,1440 npm run test:ui` — любые ширины (до 430 — телефон, до 1024 — планшет); в отчёте о горизонтальной прокрутке — блок, внутри которого виновник, элементы внутри лент с прокруткой не считаются.
- **1.41.1–1.41.4 — аудит, часть 2 (скорость):**
  - Пустые вкладки статусов — контраст 5:1. Проверка вёрстки: фильтры за кнопкой — до 900 px.
  - **CLS ~1,0 → 0–0,03:** `.header:empty` и `#app` занимают место до отрисовки — подвал не прыгает.
  - **Нагрузка (100 000 объявлений, 2 000 продавцов, 2 ядра):** лента 41 → 800 запросов/с, поиск 25 → 650, раздел `/c/…` 20 → 620, страница `/l/…` 59 → 1 080, профиль продавца 47 → 720, сортировка по цене с фильтром 21 → 960. Причины: объявления продавца перебирались по всем активным, «похожие» сортировали весь раздел, подсчёты — на каждый запрос.
  - Индексы `idx_listings_cat_date`, `idx_listings_sub_date`, `idx_listings_user_date`, `idx_listings_city_date`, `idx_listings_price` (прежние узкие удаляются при запуске). `db.memo(key, fn)` в `lib/db.js` — подсчёты выдачи и «О разделе» из памяти до изменения объявлений (временные триггеры `lg_*` меняют поколение `temp.listings_gen`; просмотры не трогают). `PRAGMA optimize` при запуске и раз в 6 ч. «Похожие» (API и снимок для поисковиков) — два запроса по индексу.
  - **Осталось для роста:** поиск редкого слова — полный просмотр `search_text LIKE '%…%'` (~200 мс на 100 000) — перейти на FTS5; глубокие страницы (`offset` 5000+) — постранично по ключу.
