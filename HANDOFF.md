## 1. Идея и позиционирование

- **Торгана** — универсальная площадка объявлений, прямой конкурент Авито: «как Авито, только честно».
- Все категории сразу, вся Россия сразу; дизайн минималистичный и премиальный, белый фон.
- Отличия: бесплатно и без лимитов для частных лиц; модерация с объяснением и апелляцией к человеку; честная выдача; ИИ (объявление по фото, поиск обычными словами, подсказка цены); защита от мошенников в чате; безопасная сделка — после подключения оплаты.

## 2. Название, домены, товарный знак

- Название — **Торгана** (torgana). Домен **torgana.ru** (REG.RU) работает; torgana.com и torgana.net на 06.11.2026 были свободны — стоит зарегистрировать.
- Товарный знак: совпадений в базе Роспатента не найдено; нужна проверка у патентного поверенного и заявка в классах МКТУ 35, 38, 42.

## 3. Дизайн

- Макеты: https://claude.ai/artifact/XxvXTaaG9CtXfwdfVJD5QT — выбрано направление **C «Поиск в центре»**.
- Логотип — знак «Т-ценник» в круге + «торгана» строчными. Акцент `#1F5E4A`, графит `#101010`, подложки `#F3F3F1`, линии `#E7E7E4`, фон `#FFFFFF`. Шрифт **Onest** — лежит на нашем сервере (`public/assets/fonts`, OFL), Google Fonts не используется.
- Иконки: `node scripts/make-icons.js` собирает `favicon.svg` и PNG 180/192/512 для экрана «Домой» из одного описания знака (квадрат на весь размер, без прозрачности, знак в безопасной зоне для maskable).

## 4. Код

GitHub: `albakovofficial/torgana`, ветка `main`. Node.js 22+, встроенная SQLite, **без npm-зависимостей** в работе сайта.

```
server.js           — сервер, API объявлений, чатов, аккаунта, почты, страниц
lib/moderation.js   — очередь проверки, страница «от и до», решения, жалобы, история объявлений
lib/support.js      — чат поддержки
lib/mailer.js       — почта: настройки, очередь с повторами, одноразовые ссылки, уведомления
lib/smtp.js         — SMTP-клиент без зависимостей;  lib/emails.js — шаблоны писем
lib/prohibited.js   — запрещённое/ограниченное: текст для Правил и проверка объявлений (один источник)
lib/legal.js        — юридические документы; реквизиты оператора из .env
lib/db.js           — схема и миграции SQLite;  lib/auth.js, http.js, search.js, ai.js, constants.js
public/             — клиент без фреймворков (assets/app.js, app.css, fonts, icons)
deploy/             — установка, автообновление, бэкапы, восстановление, службы systemd
scripts/            — db-copy.js (копия базы), make-icons.js, seed-demo.js (только локально)
tests/              — сценарии API, почты, документов, поддержки, бэкапов + проверка вёрстки
```

### Что умеет сайт
- Регистрация/вход, **подтверждение email**, **восстановление пароля** (ссылка на 1 час, одноразовая), **отдельная обязательная галочка согласия на обработку ПД** (время согласия сохраняется).
- Объявления: до 10 фото, поиск обычными словами, фильтры, оценка цены, избранное, профиль продавца.
- **Профиль** (1.2.0): фото профиля (обрезка по кругу, видно на объявлениях и в чатах; модератор может убрать фото на странице проверки), цифры (активные, продано, просмотры, в избранном), заполненность профиля, объявления с меню «⋯» (на телефоне — снизу), настройки группами: фото, имя/город/телефон, письма, **смена пароля** (другие устройства выходят), аккаунт и «Выйти»; публичный профиль в том же стиле.
- **Проверка всех объявлений**: новое объявление и каждая правка публикуются после модератора. Похожие на запрещённое (по `lib/prohibited.js`) — первыми в очереди.
- **Модерация** (`/admin`): вкладки «На проверке», «Жалобы», «Поддержка», «Апелляции», опубликованные/отклонённые/проданные/снятые, «Почта». Страница проверки `/admin/l/:id` — все фото и поля, подсветка подозрительных слов, продавец (регистрация, почта, телефон, сколько объявлений и отклонений, жалобы, блокировка), полная история объявления (правки по полям, решения, апелляции, жалобы — кто и когда), кнопки «Опубликовать / Отклонить / Заблокировать», после решения — следующее из очереди. Отказ по апелляции с ответом.
- **Жалобы** — «Пожаловаться» на объявлении; модератор закрывает с комментарием.
- **Приложение на экране «Домой»**: страницу можно обновить, потянув её вниз (как в ALBAKOV; в браузере телефона — свой жест браузера). Обновление мягкое, а если на сервере новая версия сайта — страница перезагружается целиком.
- **Чаты** с предупреждением о мошенниках; **«Поддержка Торганы»** закреплена первой в «Сообщениях», модераторы отвечают во вкладке «Поддержка».
- **Письма** (после подключения почты): подтверждение email, сброс пароля, новые сообщения (не чаще раза в 15 мин на диалог, только непрочитанные), решения модерации, ответы поддержки; отписка в один клик и переключатели в профиле.
- **Документы** (`/page/...`): `terms` — соглашение (в т. ч. ст. 15.7 149-ФЗ для правообладателей, рекомендательные технологии), `rules` — правила с 18 категориями запрещённого со ссылками на законы и разделом «Разрешено с условиями», `privacy` — политика ПД (152-ФЗ), `consent` — согласие на обработку ПД, `contacts` — реквизиты и контакты (149-ФЗ ст. 10). Реквизиты ИП — в подвале.
- Защита: проверка Origin, ограничения частоты, проверка изображений, CSP; версии файлов интерфейса (`app.js?v=хеш`) — обновления сразу доходят до браузеров.

### Проверки и порядок выкладки
- `npm test` — 89 сценариев на временной базе (API, почта, документы, поддержка, бэкапы, автообновление, профиль); `npm run test:ui` — 36 страниц на телефоне (375 px) и компьютере (72 проверки), скриншоты в `tests/screenshots`.
- GitHub Actions (`.github/workflows/check.yml`) гоняет обе проверки на каждый pull request, в том числе `main → release`.
- **Как в ALBAKOV — две ветки:** `main` (рабочая, сайт от неё не меняется) и **`release`** (то, что на сайте). Отдельных веток под доработки нет.
- **Каждая доработка — коммит в `main` с номером версии в названии**: «1.1.0: что сделано». Номер в `package.json` повышается в том же коммите: новая возможность — средняя цифра (1.1.0 → 1.2.0), исправление — последняя (1.2.0 → 1.2.1). Затем pull request **`main → release`** с тем же названием; владелец нажимает Merge («Create a merge commit») — это и есть выпуск.
- Сервер каждые 30 секунд смотрит `release`. Новую версию он сначала проверяет во временной папке (синтаксис + сценарии API на временной базе), затем делает копию базы (5 последних в `data/update/db`), ставит код и перезапускает сайт. Если сайт не ответил, сервер откатывает версию. Неудачная версия больше не ставится, пока в `release` не появится следующая. Ставятся только версии новее работающей: если `release` откатили назад или в нём «боковая» ветка, сервер её не ставит (в панели — объяснение).
- Номер работающей версии и состояние видно в «Модерация → Версия сайта», на сервере: `sudo torgana-autoupdate --status` (журнал `data/update/update.log`), `sudo torgana-autoupdate` — проверить сейчас. Ветку можно сменить через `UPDATE_BRANCH` в `.env`.
- Защита веток в GitHub **не включена** — можно включить для `release`: Settings → Branches → «Require status checks to pass» → `check`.
- Pull request сливает владелец (кнопка Merge в GitHub).

## 8. Пожелания владельца

- Перед каждой доработкой показывать план и начинать после подтверждения.
- **Как в ALBAKOV:** две ветки — `main` и `release`; доработка — коммит в `main` «X.Y.Z: что сделано» с номером в `package.json` (новая возможность — средняя цифра, исправление — последняя), выпуск — PR `main → release`, Merge нажимает владелец. Отдельных веток под доработки не заводить.
- Владелец — torganaofficial@yandex.ru; albakovofficial@mail.ru модератором больше не является.
- Обновления выкатываются уже рабочими и не ломают мобильную версию (тесты + проверка вёрстки обязательны).
- Стиль C, белый фон, премиально и удобно.
- Никаких демо-режимов на боевом сайте: неподключённое честно помечено или скрыто.
- Тексты сайта и документов описывают процессы ровно так, как они работают.
- В коде **не дублировать функции** — расширять или объединять существующие; удалять лишний код и изображения.
