# Торгана

Площадка объявлений по всей России. Node.js 22+, встроенная база SQLite, **ноль внешних зависимостей** — не нужно `npm install`.

## Что умеет

- **Регистрация и вход** (email + пароль, пароли хранятся в виде scrypt-хеша, сессии в httpOnly-cookie).
- **Объявления**: до 10 фото (сжимаются в браузере), 10 категорий, цена или «договорная», единицы (мес, сутки, м²…), состояние, город, доставка.
- **Поиск обычными словами**: «коляска до 15 000 с доставкой в Казани» — сайт сам понимает цену, доставку и город. Плюс фильтры и сортировка.
- **Оценка цены**: «Ниже рынка / в рынке / выше рынка» и подсказка цены при размещении — по похожим объявлениям.
- **Избранное**, **публичный профиль продавца**, **похожие объявления**.
- **Чат покупателя и продавца** со счётчиком непрочитанных и **предупреждением о мошенниках**, если собеседник зовёт в мессенджеры или просит оплату по ссылке.
- **Личный кабинет**: статусы «Активные / На исправлении / Проданные / Сняты», редактирование, удаление.
- **Проверка всех объявлений**: новое объявление и каждая правка публикуются после модератора; похожие на запрещённое (по списку из Правил) — первыми в очереди. Страница проверки «от и до»: все фото и поля, подсвеченные слова, продавец, история объявления с изменениями, жалобы; «Опубликовать / Отклонить / Следующее».
- **Модерация с объяснением**: причина отклонения, апелляция, отказ по апелляции с ответом, блокировка авторов, статистика.
- **Жалобы** на объявления («Пожаловаться») и **чат поддержки**, закреплённый первым в «Сообщениях»; модераторы отвечают во вкладке «Поддержка».
- **ИИ-заполнение по фото** (если указан `ANTHROPIC_API_KEY`): название, категория, состояние и описание.
- Адаптивный дизайн: на телефоне — плавающее нижнее меню.
- Защита: проверка Origin на изменяющих запросах, ограничение частоты, проверка файлов изображений, CSP-заголовки.

- **Письма** (после подключения почты в «Модерация → Почта»): подтверждение email, восстановление пароля по одноразовой ссылке (1 час), уведомления о новых сообщениях (не чаще раза в 15 минут на диалог, только непрочитанные) и о решениях модерации, отписка в один клик и переключатели в профиле. Очередь с повторами и журнал отправки. Пока почта не подключена, связанные кнопки на сайте скрыты.

**Не подключено:** приём оплаты («Безопасная сделка» показана как «Скоро») — нужен договор с платёжной системой (например, ЮKassa).

## Запуск на своём компьютере

```bash
cp .env.example .env        # укажите ADMIN_EMAIL
npm start                   # или: node server.js
```

Откройте http://localhost:3000. Зарегистрируйтесь с email из `ADMIN_EMAIL` — появится раздел «Модерация» в профиле.

Посмотреть сайт с тестовыми объявлениями (только локально!):

```bash
npm run seed-demo
```

## Запуск на сервере (VPS, Ubuntu)

1. Установите Node.js 22 LTS:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
   ```
2. Скопируйте папку проекта, например в `/var/www/torgana`, создайте `.env` по образцу.
3. Сервис systemd `/etc/systemd/system/torgana.service`:
   ```ini
   [Unit]
   Description=Torgana
   After=network.target

   [Service]
   WorkingDirectory=/var/www/torgana
   ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server.js
   Restart=always
   User=www-data
   Environment=NODE_ENV=production

   [Install]
   WantedBy=multi-user.target
   ```
   ```bash
   sudo chown -R www-data:www-data /var/www/torgana
   sudo systemctl enable --now torgana
   ```
4. nginx как прокси + HTTPS (certbot):
   ```nginx
   server {
     server_name torgana.ru www.torgana.ru;
     client_max_body_size 12m;
     location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```
   ```bash
   sudo certbot --nginx -d torgana.ru -d www.torgana.ru
   ```

## Проверка перед выкладкой

```bash
npm test          # сценарии API на временной базе (боевую не трогает)
npm run test:ui   # вёрстка на телефоне (375 px) и компьютере, скриншоты в tests/screenshots
npm run check     # всё сразу
```

Для `test:ui` нужен Playwright с Chromium (`npm i --no-save playwright && npx playwright install chromium`).

Порядок работы:
1. Каждая доработка — в отдельной ветке и pull request.
2. GitHub сам прогоняет проверку (`.github/workflows/check.yml`) и прикладывает скриншоты.
3. В `main` сливается только то, что прошло проверку. На сайт `main` сам не попадает.
4. **Выпуск** — слияние `main → release`: GitHub → Actions → «Выпуск» (проверка + fast-forward) или pull request `main → release`.
   Сервер каждые 30 секунд проверяет `release` (`deploy/update.sh`). Новую версию он проверяет во временной папке,
   делает копию базы, ставит код, перезапускает сайт и проверяет, что тот отвечает. Если нет — откатывает версию,
   а неудачную больше не ставит, пока не появится следующая. Ставятся только версии новее работающей. Состояние — «Модерация → Версия сайта» и
   `sudo torgana-autoupdate --status` на сервере (команду ставит `deploy/apply-units.sh`).

## Резервные копии

Два уровня, оба включены:

1. **Весь диск сервера** — план «torgana-daily» в Selectel (Облачная платформа → Бэкапы), каждый день в 05:00,
   раз в неделю полная копия, хранятся последние 2 полные цепочки (≈2–3 недели). Копии лежат отдельно от сервера.
   *Сервер потерян или сломан целиком:* панель Selectel → Бэкапы → torgana-daily → нужная дата → «Восстановить»
   (на тот же диск или в новый диск, из которого создаётся сервер). Восстанавливается всё: система, сайт, база,
   фото, настройки, сертификаты.
2. **Сайт по отдельности** — `deploy/backup.sh` каждый день в 04:00 (служба `torgana-backup`), 14 дней:
   - `backups/db/torgana-ДАТА.db.gz` — база (согласованная копия, сайт не останавливается) и версия кода;
   - `backups/uploads/ДАТА/` — снимок всех фото (жёсткие ссылки, место почти не занимает);
   - `backups/config/config-ДАТА.tar.gz` — `.env`, nginx, HTTPS-сертификаты, службы, ключ GitHub.

   *Нужно откатить данные* (удалили лишнее, ошибка в обновлении) — на сервере под root:
   ```bash
   bash /var/www/torgana/deploy/restore.sh list              # какие даты есть
   bash /var/www/torgana/deploy/restore.sh 2026-11-07        # база и фото на эту дату
   bash /var/www/torgana/deploy/restore.sh 2026-11-07 --config   # + настройки сервера
   ```
   Перед восстановлением текущее состояние сохраняется в `backups/before-restore-ВРЕМЯ/` — откат можно отменить.

Полный цикл «копия → поломка → восстановление» проверяется тестом `tests/backup.test.js`.
После изменений в `deploy/*.service` и `deploy/*.timer` выполните на сервере `bash /var/www/torgana/deploy/apply-units.sh`.

## Перед публичным запуском

- Документы (соглашение, правила, политика, согласие на обработку ПД) — в `lib/legal.js`, реквизиты оператора — из `.env` (`OPERATOR_NAME`, `OPERATOR_INN`, `OPERATOR_OGRNIP`, по умолчанию ИП Албаков И. М.). Покажите документы юристу и подайте уведомление об обработке ПД в Роскомнадзор.
- Список запрещённого — `lib/prohibited.js`: из него строится раздел «Запрещено» в Правилах, и по нему же объявления проверяются при публикации (похожие уходят модератору «на проверку»).
- Иконки: `node scripts/make-icons.js` пересобирает `favicon.svg` и PNG для экрана «Домой» из одного описания знака.
- Укажите `SUPPORT_EMAIL`.
- Подключите почту: «Модерация → Почта» (SMTP.BZ: кнопка «Заполнить для SMTP.BZ», логин и пароль из личного кабинета), отправьте тестовое письмо. Домен отправителя подтвердите в SMTP.BZ и добавьте его записи SPF/DKIM в DNS.
- Для работы с персональными данными граждан РФ сервер должен находиться в России (152-ФЗ).

## Структура

```
server.js            — сервер и все API
lib/                 — база, авторизация, поиск, ИИ, константы (категории, города)
public/index.html    — оболочка сайта
public/assets/       — app.js (интерфейс), app.css (дизайн), иконка
scripts/seed-demo.js — тестовые данные для локального просмотра
```
